# 程序视觉与行为规格书

从代码里挖出来的**真实数值**。这是分镜可以照着做的依据，不是审美描述。
每个数字后面标了出处文件，便于复核。

> **先纠正上一版计划书的一个错**：我写了「`m_fov = 6.15`，等于 331 mm 长焦」。那是 `NativeScene.h` 里的**初始值**，`updateCamera()` 每帧会把它 lerp 到由 `span/distance` 算出的目标值。浏览页收敛后是 **≈21.85°**（36 mm 画幅约 93 mm）。详情页才是长焦（≈4.7°，约 440 mm）。下面按收敛值。

## 一、场景：不是书架，是五列叠压的卡匣

`NativeScene.cpp:cellPosition`

```
x = (lane − 2) × 5.2      lane ∈ [0,4]        → 横向 5 列，列距 5.2
y = −4.6                                      → 卡片底面基准
z = (row − 15.5) × 0.62   row ∈ [0, …]        → 纵深方向，行距 0.62
```

卡片包围盒（`NativeSceneCamera.cpp:intersectsCard`）：

```
position + (−2.8, −0.3, −1.2)  →  (+2.8, +4.1, +1.2)
即 5.6 宽 × 4.4 高 × 2.4 厚
```

**注意**：`intersectsCard` 的 ±1.2 是**拾取盒**，不是几何。实测 `archive-cassette.glb` 的真实尺寸是 **5.0104 × 0.3764 × 3.7000**（宽 × 厚 × 高）——卡片是一片 **3.76 mm 厚的薄板**，不是 2.4 厚的盒子。

所以真正的空间关系是：

```
行距 0.62   −  厚 0.376  =  间隙 0.244   （间隙占 39%）
列距 5.2    −  宽 5.01   =  缝 0.19
```

**5 列 × 40 片薄板，间距 0.62，像百叶，不像书架。** 这就是截图里那种「一片片斜插的板、板缝里透出光」的来源——不是叠压，是**留缝**。

我做的 34 个镜头里，卡片全部是 0 厚度的发光面片，间距是均匀的网格——两样都不对。

## 三、镜头：一条带名字的运镜曲线

`NativeSceneCamera.cpp:updateCamera`

```
orbit  = smooth((shot − 22.6) / 1.6)           // 环视开始
settle = smooth((shot − 24.25) / 2.25)         // 落位

yaw       = (89 − 22·orbit − 8·settle)°        // 从 89° 侧视转向
elevation = (3 + 40·smooth((shot−21.96)/0.22) − 8·orbit − 16·settle)°
span      = lerp(lerp(10.8, 10.3, orbit), 7.33, settle)   // 画幅竖向覆盖的世界高度
distance  = lerp(lerp(28 + 7·orbit, 140, settle), 72, detail)
aim       = { −1.091, lerp(−2.55 + 0.4·orbit, −0.045, settle), lerp(2.48, 0.481, settle) }
fov       = 2·atan(span / (2·distance))        // 由 span 和距离反推，不是手调的
```

**浏览页收敛值**：yaw 89°, elevation 3°, span 10.8, distance 28 → **fov ≈ 21.85°**，相机在目标点外 28 个单位。
**详情页收敛值**：span 7.33→5.9, distance 140→72 → fov ≈ 4.7°。

**构图偏移（最容易被忽略的一条）**：

```cpp
m_projection.values[8] += 0.16 * archiveOffset;   // 水平
m_projection.values[9] += 0.20 * archiveOffset;   // 垂直
```

浏览态下视锥整体**偏 16% / 20%**，把档案挤到左下，右上留白给界面。这不是构图「感觉」，是写进投影矩阵的常数。我的分镜构图居中 —— 所以怎么调都不像。

**雾**（`updateCamera` 末段）：

```
fogNear = 渲染距离 + (5 − 4·theme)      // 亮色态 5，暗色态 1
fogFar  = 渲染距离 + (25 − 9·theme)     // 亮色态 25，暗色态 16
```

雾带只有 **20 个单位深**（暗色态仅 15），卡片一到就化进背景。

## 四、表面着色：一束光 + 一张烘焙图

`Qt/shaders/enhancement/opticalSurface.frag`

```glsl
const vec3 KEY_LIGHT = normalize(vec3(0.0, 0.55, 0.84));   // 上方略偏前
diffuse = base * (0.55 + 0.45 * max(dot(n, l), 0.0));      // 环境项 55%
spec    = pow(max(dot(n, normalize(l + v)), 0.0), mix(20, 90, gloss)) * mix(0.18, 0.85, gloss);
```

- 环境项 **0.55** —— 一半以上的亮度不来自方向光，所以画面永远不发死黑。
- 次表面光照来自**烘焙光场**：`archive-baked-light.bin`（6.0 MB，8 层高度切片）+ `archive-baked-normal.bin`（256 KB）+ `archive-baked-surface.bin`（13.5 MB）。`RhiScene.cpp` 注释写明：**不创建实时透射、阴影、AO、景深或光晕**。
- 玻璃壳用菲涅耳近似代替折射：`fresnel = pow(1−ndv, 5)`, `rim = pow(1−ndv, 2.2)`, `edge = smoothstep(0.55, 0.98, rim)`。
- 光学薄膜（CD 表面那一圈玻璃反射）：`spec = pow(..., 160) * 1.8` + `rim = pow(1−ndv, 3) * 0.30`。
- **`clarity` 就是「霜层」**：clarity 越低，玻璃越磨砂、唱片封面被 9 抽样模糊。解密动画驱动的就是这个值。

## 五、成片调色：ACES + 纸洗

`opticalFinalFragment.frag` + `opticalCommon.glsl`

```glsl
rgb = outputColor(aces(hdr, mix(0.76, 0.98, theme)));   // ACES，曝光随昼夜 0.76→0.98
```

ACES 用的是 Three.js r183 那套 mat3 + 有理式，不是 Blender 的 AgX。**这一条我全错了**：我给 Blender 设了 AgX。

然后是「纸洗」——把渲染结果压回纸张：

| 层 | 亮色态 | 暗色态 |
|---|---|---|
| 纸色 | `#DEDBD7` | `#11181B` |
| 顶部 | `0.72 × (1 − y/0.50)` | `0.82 × (1 − y/0.36)` |
| 底部 | `0.72 × (1 − (1−y)/0.35)` | `0.84 × (1 − (1−y)/0.35)` |
| 椭圆 | 心 (0.42, 0.47)，半径 (.58, .53)，边缘强度 0.19 | 心 (0.48, 0.48)，同半径，边缘 0.48 |
| 右侧 | x<0.59 → 0；0.59–0.68 → 0.92；>0.68 → 1.0 | 同 |

也就是说：**画面四周（尤其右边缘）被纸色吃掉，3D 只活在一个柔和的椭圆窗口里**。右上角那块留白不是「没东西」，是**纸洗洗掉了**。

还有一层「屏幕外柔化」：9 抽样，半径随 `|uv.y − 0.52|` 放大到 6 texel —— 上下边缘自然虚化（假的景深）。

## 九、结论：三条否决各自的技术根因

1. **「界面和程序风格相差太大」** → 我从没用过 10/11/12/13/14/15/22/32/50.75 这套字号，没用过 0.15 px 发丝线，没用过 `left 40 / x 326 / rowHeight 54` 的网格，也没做纸洗调色。界面和 3D 在程序里是**同一张纸上的两件事**。
2. **「没有间接体现程序功能和卖点」** → 因为我把注意力放在「形状」上，而程序的功能全是**动作**：抽出、归位、涟漪、扫描、昼夜扩散、解密。这些动作有精确的物理参数，照抄就能「演出功能」。
3. **「场景和模型几乎没有复刻」** → 卡片是 11 部件、19,050 顶点的实体，我用了发光面片；档案是叠压 74% 的卡匣走廊，我摆了书架；运镜有带名字的曲线，我手调了机位。
